FINDINGS THAT SHAPED THE DESIGN (verified against a real Claude Code session log on this machine)
  - Real logs write ONE LINE PER CONTENT BLOCK, each repeating the same usage. Summing lines overcounts
    ~4x (real log: naive $13.61 vs deduped $3.21; independent raw-node recompute = $3.2068). Parser dedupes
    on message.id|requestId and keeps the largest output_tokens.
  - Cache writes have two TTL tiers (5m = 1.25x input, 1h = 2x input); logs carry cache_creation.ephemeral_*.
    Real session used the 1h tier, so a flat 1.25x would have undercharged.
  - Cache-READ rate is model-specific (0.025x-0.1x of input). Encoded per model, not as a flat 10%.

KNOWN LIMITATIONS (do not paper over)
  - Subagent attribution via Task-call lineage is UNVERIFIED against real subagent logs: the only real log
    available had no sidechain lines. It is covered by synthetic fixtures built from the documented fields.
  - Pricing: 8 models fully documented; 5 older models (opus-4-6/4-7/4-8, sonnet-4-6, haiku-4-5) carry an
    ASSUMED 0.1x cache-read rate and are flagged source:"assumed" in every report. Models absent from the
    table (e.g. haiku-5-5, which has a >100K-token price tier) are reported as UNPRICED, never guessed.
  - Fast-mode (speed:"fast") price multipliers are not modelled.

DESIGN DECISIONS (router)
  - Offload only what is fully MECHANICAL. Each rule: (1) does the prompt concern my domain? (2) reasoning
    verb (fix/explain/why/review/...)? -> decline (3) positive intent? Explicit task.operation skips 1-3.
  - JSON formatting uses a token-preserving parser, NOT JSON.parse/stringify, which corrupts data
    (12345678901234567890 -> ...67000, 1.0 -> 1, duplicate keys dropped).
  - Anything the local script cannot fully evaluate is DECLINED, not approximated: JSON Schema $ref/if/format,
    catastrophic-backtracking regexes, unrecognised test-runner output, oversized (>2M chars) input.
  - A throwing script never fails the agent: the rule is skipped and the LLM handles the task.
  - route() is pure (logging happens only in handle()), so dry runs cannot double-count savings.
  - Savings are a MODELED COUNTERFACTUAL, conservative by construction: payload at plain input rate (not the
    1.25x write rate), output = script answer with no model preamble, re-read context = 0 unless the task
    states contextTokens. Token counts are estimated (chars/4; injectable) because the call never happened.
    Unpriced models are still offloaded but claim $0 and are counted in unpricedCalls.

KNOWN LIMITATIONS (router)
  - lint-check is a built-in hygiene linter over in-memory files, not a wrapper around a project's ESLint.
  - go test is supported with -v output (or any output containing --- PASS/FAIL/SKIP lines) only.
  - Rule intent detection is English-prompt regex; use task.operation for reliable routing.

BUGS FOUND BY RUNNING IT (not by unit tests)
  - React hydration error #418: server rendered $6.77, browser $6.88 for the same seed. Cause: a shuffle written as
    .sort(() => rng.next() - 0.5); a stateful comparator makes rng consumption depend on each engine's sort internals,
    so the "seeded" simulator was not portable between Node and Chromium. Fixed with a Fisher-Yates rng.shuffle, a
    guard test banning comparator shuffles/Math.random/clock in src/lib, and a pinned seed-42 snapshot.
  - "Tokens avoided" headline counted cached context the avoided call would merely have re-read (2.5M tokens for 36 JSON
    checks). Now counts fresh tokens only (5,197); the re-read context stays priced in the dollars.
