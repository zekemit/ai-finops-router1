# CLAUDE.md — ai-finops-router

AI Token & Unit-Economics Observability Dashboard + Deterministic Router for multi-agent Claude Code workflows.

## Session-recovery protocol (read first)

Remote sessions disconnect. State lives in git, not in memory.

1. Read `progress.txt` → what phase is current, what is done.
2. Read `tests.json` → last recorded test status (generated by `npm run record-tests`; never hand-edit).
3. `git log --oneline` + `git status` → confirm nothing is uncommitted.
4. Resume from the first unchecked item in `progress.txt`.

Never leave uncommitted work between phases. Commit after each phase passes its tests.


## TypeScript rules (strict, non-negotiable)

- `strict: true`, `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true`, `noImplicitOverride: true`.
- **No `any`** — explicit or implicit. No `as any`, no `@ts-ignore`, no `@ts-expect-error` to silence real errors.
- Use `unknown` at trust boundaries (JSONL lines, API payloads) and narrow with type guards / parsers.
- No non-null assertions (`!`) in library code; handle the `undefined` case.
- Money is computed from integer token counts × per-million-token USD prices. Round only at presentation time.
- Library code is pure: no I/O inside cost math, routing rules, or aggregation. I/O lives in CLI entry points and the dashboard API layer.

## Architecture boundaries

- `interceptor` owns **types, pricing tables, and cost math**. It is the single source of truth for `AgentName`, `TelemetryEvent`, `ModelPricing`.
- `router` may import from `interceptor`. `interceptor` must **never** import from `router` or `dashboard`.
- `dashboard` consumes both packages through their public `index.ts` exports only — no deep imports into `src/`.
- Savings math lives in exactly one place per concern: cache savings in `interceptor`, offload savings in `router`. The dashboard aggregates; it never re-derives prices.
- Routing is **deterministic**: same payload in → same decision out. No randomness, no clock reads, no network in rule evaluation. The simulator may use a seeded PRNG.

## Engineering discipline

- **TDD**: write the failing test, watch it fail for the right reason, then write minimal code. Never delete or weaken a failing test to force a pass — fix the implementation.
- No placeholder `TODO` comments in core logic. Ship complete implementations.
- Verify before claiming done: run the commands, read the output.
- Commit messages follow Conventional Commits (`feat(scope):`, `chore:`, `fix:`, `test:`, `docs:`).
